# Export Module Design

## Overview

The `export.py` module provides CSV export functionality for data analysis, backup, and reporting. It supports three export types: habits, logs, and streaks.

## Architecture

### HabitExporter Class

Single class that handles all CSV export operations.

```python
class HabitExporter:
    def __init__(self, db: Database, output_dir: str = "."):
        self.db = db
        self.output_dir = Path(output_dir)
        self.output_dir.mkdir(exist_ok=True)
```

**Design Rationale:**
- Encapsulates export logic
- Manages output directory creation
- Single responsibility per method
- Database dependency for data access

## Export Types

### 1. export_habits()

Exports all habit definitions (including archived).

**Parameters:**
- `filename` (str): Optional custom filename (auto-generated by default)

**Returns:** Path to exported CSV file

**CSV Columns:**
- `id`: Habit ID
- `name`: Habit name
- `description`: Habit description (may be empty)
- `created_at`: ISO timestamp when created
- `archived`: 0 (active) or 1 (archived)

**Filename Format:**
```
habits_20260508_041738.csv
        └─ timestamp for uniqueness
```

**Use Cases:**
- Backing up habit definitions
- Migrating habits to another system
- Analyzing habit creation patterns
- Archiving historical habit data

**Example Output:**
```csv
id,name,description,created_at,archived
1,Morning Jog,30 min morning jog,2026-01-01T08:00:00,0
2,Meditation,10 min meditation,2026-02-15T07:30:00,0
3,Reading,Read 20 pages,2026-01-20T20:00:00,1
```

**Error Handling:**
- Raises `ValueError` if no habits exist
- Directory creation handled automatically

### 2. export_logs(start_date, end_date, filename=None)

Exports log entries for a specific date range.

**Parameters:**
- `start_date` (str): Start date in YYYY-MM-DD format
- `end_date` (str): End date in YYYY-MM-DD format
- `filename` (str): Optional custom filename

**Returns:** Path to exported CSV file

**CSV Columns:**
- `date`: Date of log entry (YYYY-MM-DD)
- `habit`: Habit name (joins with habits table)
- `completed`: "Yes" or "No" (human-readable)
- `notes`: User notes (may be empty)

**Filename Format:**
```
logs_2026-05-01_to_2026-05-08_20260508_041738.csv
        └──────────────────────┘  └─ timestamp
           date range
```

**Use Cases:**
- Exporting time-boxed data for analysis
- Creating reports for specific periods
- Backing up completion history
- Importing to spreadsheet applications

**Example Output:**
```csv
date,habit,completed,notes
2026-05-08,Morning Jog,Yes,Felt great!
2026-05-08,Meditation,Yes,
2026-05-07,Morning Jog,Yes,
2026-05-07,Meditation,No,Too tired
2026-05-06,Morning Jog,No,Sick
```

**Process:**
1. Iterate all active habits
2. Query logs for each habit in date range
3. Join habit name with log data
4. Format completed as Yes/No (user-friendly)
5. Write to CSV

**Error Handling:**
- Raises `ValueError` if no logs found for date range
- Date format errors caught by database layer

**Edge Cases:**
- Single-day range: Returns only that day's logs
- No logs for range: Returns empty (raises error)
- Habits added after start_date: Still included if logs exist

### 3. export_streaks(filename=None)

Exports streak summary statistics for all habits.

**Parameters:**
- `filename` (str): Optional custom filename

**Returns:** Path to exported CSV file

**CSV Columns:**
- `habit`: Habit name
- `current_streak`: Days in current consecutive streak
- `longest_streak`: Best streak ever achieved
- `total_completions`: Total completed days

**Filename Format:**
```
streaks_20260508_041738.csv
        └─ timestamp
```

**Use Cases:**
- Habit performance dashboard
- Tracking progress over time
- Identifying strongest/weakest habits
- Goal tracking and milestone reporting

**Example Output:**
```csv
habit,current_streak,longest_streak,total_completions
Morning Jog,10,12,47
Meditation,5,7,30
Reading,1,3,12
```

**Process:**
1. List all active habits
2. For each habit, call `get_habit_stats()`
3. Write stats to CSV

**Design Notes:**
- Only includes active habits (archived excluded)
- Statistics computed from database and utils functions
- Current snapshot at time of export

## Filename Generation

### Auto-generated Format
```
{type}_{date_range}_{timestamp}.csv
```

**Components:**
- `type`: habits, logs, or streaks
- `date_range`: Only for logs export (start_to_end)
- `timestamp`: Always included for uniqueness (YYYYMMdd_HHMMSS)

**Benefits:**
- Unique filenames prevent overwrites
- Easy to sort chronologically
- Recognizable content from filename

### Custom Filename
Users can provide their own filename:
```python
exporter.export_habits(filename="my_habits_backup.csv")
```

**Design Notes:**
- Custom names bypassed auto-generation
- User responsible for uniqueness
- Useful for known workflows

## CSV Format Details

### CSV Writer Configuration
```python
writer = csv.DictWriter(f, fieldnames=[...])
```

**Decisions:**
- Use DictWriter for clarity and type safety
- DictFieldnames ensures consistent column order
- Quotes only when necessary (default behavior)

### Data Format
- **Dates**: ISO format (YYYY-MM-DD)
- **Booleans**: Human-readable (Yes/No) for logs
- **Numbers**: Integer format for counts
- **Empty Fields**: Empty strings (not NULL)

### CSV Compatibility
- Standard RFC 4180 format
- Compatible with Excel, Google Sheets, pandas, R
- UTF-8 encoding (default)
- CRLF line endings on Windows (handled by csv module)

## Error Handling

### Validation Errors
```python
raise ValueError("No habits to export")
raise ValueError("No log entries found for the specified date range")
```

**Pattern:** Explicit error messages for user clarity

### File System Errors
- Directory creation: `mkdir(exist_ok=True)` prevents errors
- File writing: OS exceptions bubble up (rare case)

### Design Philosophy
- Fail fast with clear messages
- No silent failures (always raise on empty data)
- Let OS errors surface (indicates system issues)

## Performance Characteristics

### Database Queries
- `export_habits`: Single SELECT (all habits)
- `export_logs`: Single loop with query per habit (N+1 pattern)
- `export_streaks`: Single loop with function per habit

### Memory Usage
- All results loaded into memory before writing
- Acceptable for typical use cases (hundreds of entries)
- Could be optimized with streaming for large datasets

### File I/O
- Single write operation per export
- CSV module handles buffering efficiently

## Design Decisions

### 1. Three Export Types (Not One Generic)
- **Why**: Different purposes need different columns
- **Why**: Logs export requires date filtering
- **Alternative**: Single export with optional columns (less clear)
- **Benefit**: Focused, purposeful exports

### 2. Auto-generated Filenames with Timestamps
- **Why**: Prevents accidental overwrites
- **Why**: Creates audit trail of exports
- **Alternative**: Fixed names (loses history)
- **Trade-off**: Slightly more files on disk

### 3. Human-readable Format
- **Why**: Open in any text editor
- **Why**: Compatible with all spreadsheet apps
- **Alternative**: JSON (less compatible), binary (harder to inspect)

### 4. Active Habits Only (for Streaks Export)
- **Why**: Current performance focus
- **Alternative**: Include archived (dilutes insights)
- **Flexibility**: Could add `--include-archived` flag

### 5. Query Per Habit (N+1 Pattern)
- **Why**: Simple, clear implementation
- **Alternative**: Single JOIN query (more complex)
- **Trade-off**: Slightly less efficient but acceptable for typical datasets

### 6. Error on Empty Data
- **Why**: Prevents accidental export of nothing
- **Why**: Clear feedback to user
- **Alternative**: Export empty file (confusing)

## Future Enhancements

1. **Streaming Export**: For very large datasets
2. **Format Options**: JSON, Excel, PDF exports
3. **Filters**: Export by habit category, streak range
4. **Import**: Reverse operation for data migration
5. **Scheduling**: Automatic periodic exports
6. **Cloud Upload**: S3, Google Drive integration
7. **Email**: Send exports via email
8. **Compression**: ZIP archives for space efficiency

## Testing Strategy

### Unit Tests
- Happy path for each export type
- Date ranges (single day, long range)
- Empty data (raises ValueError)
- Custom filenames
- File content validation

### Integration Tests
- Create data → export → verify contents
- Multiple habits with different patterns
- Logs across date boundaries
- Streak calculations in export match in-app

### Validation
- CSV structure (proper headers, consistent columns)
- Data accuracy (matches database)
- File integrity (readable, valid format)
- Edge cases (no habits, no logs, special characters)
